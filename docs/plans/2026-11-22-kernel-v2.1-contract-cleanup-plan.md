# 个人日报内核 v2.1 去旧契约残留重构清单

## 1. 目标与定位

- **基线提交**：`244ebd7`（v2 重构提交 `a019f87` + 发布文件换行同步 `244ebd7`），对应已部署正式包 `.releases/rust-20261122-offline-v2-04`。
- **当前规模基线**：工作区 `src/**/*.rs` 共 **35,637 物理行 / 31,870 非测试行 / 3,767 内联测试行**。
- **核心定位**：**不做整库架构重扫，不触碰已验证的核心解析算法与报告业务兼容**。仅定向拆除 `rust/daily_parsers/src/settings` 与 `rust/daily_report/src/scan` 中遗留的旧跨进程 `scanner_contract` v1 信封、死字段与无效装配逻辑。
- **预期收益**：净减 **~2,100 ～ 2,350 行真实非测试代码**（总非测试行由 31,870 降至 **~29,500 ～ 29,800**），并消除每次正式扫描白白拼接并丢弃最多 180,000 字 `envelope.file_context` 字符串的内存与 CPU 开销。
- **度量原则**：**严禁通过把 `src/**/*.rs` 中现有的 3,767 行内联测试挪到 `tests/` 来制造虚假行数下降**；所有规模门槛一律以非测试源码行（`non_test`）衡量。

## 2. 不动清单（红线与兼容边界）

以下模块和外部契约在 v2.1 清理中**严禁破坏**：

1. **解析与 PDF 子进程内核零改动**：
   - `rust/daily_parsers/src/office/**`、`text/**`、`discovery/**`、`contract/content_audit.rs`、`pdf_wire.rs`（除迁入 `SourceGuardKind` 外的现有帧协议）与 `rust/pdf_worker/**`。
2. **报告业务与历史兼容零改动**：
   - `rust/daily_report/src/reports/**`、`model/**`、`store/**`、`search/**`、`publish.rs`、`health.rs`、`snapshots.rs`、`processing_cache.rs`、`maintenance/**`、`operations/rollback.rs`、`run/personal.rs`（完整保留 v1 报告库、FTS5 检索、v5～v8 冻结回放与回退）。
3. **`ScannerSettings` 序列化契约不可破**：
   - `rust/daily_report/src/config.rs` 第 577 行 `fingerprint_fields` 直接序列化 `self.scanner`，且 `ScannerSettings` 带 `#[serde(deny_unknown_fields)]` 负责解析 `config-rust/settings.yaml`。因此 `ScannerSettings` 的全部字段名、YAML/JSON 映射与 `raw.validate()` 必须完整保留。
   - `config.rs` 第 458–466 行 `take_scanner_path(scanner_map, "office_worker_path", ...)` 继续容忍旧配置文件中的 `office_worker_path` 字段，只移除内部结构体传递的假路径。
4. **`scan_cache_v4.sqlite3` 兼容边界**：
   - 保留三表结构（`parse_cache`、`pdf_negative_cache`、`scan_snapshots`）与 `SnapshotManifest` 的 8 字节前缀 + JSON 元组布局。默认保留 `RefillRoundAudit`（13 行）以免现有 v4 缓存快照失效；若连带清理 `scheduler.rounds`（可再减约 50 行），须同步提升 `SNAPSHOT_POLICY`（例如改为 `scan_snapshot_v5`）并接受升级后首次自动重建缓存。
5. **`doctor --strict` 外部脚本契约**：
   - `scripts/release_common.ps1` 与 `scripts/set_model_service.ps1` 核验顶层 `status`、`build`、`templates`、`parser_content_identity`、`model.calls`；`scanner` 字段只需保留可读的 `status` 与 `checks`（含 `scan_cache_v4`、`office_parser`、`pdf_worker`），无需旧跨进程协议的 `contract`、`protocol_version`、`request_id`。
6. **M4 基准对比驱动边界**：
   - `.artifacts/kernel-v2-20261122/bench/v2_evidence.py` 消费 `examples/kernel_v2_bench.rs` 输出的 `{envelope, evidence, sources, pdf_runtime}`。默认将旧对比所需的 JSON 投影包装移出生产 `src/`，放进 `examples/`（或确认不再重跑 Phase-3 对照后同步精简驱动），既保住历史对比脚本，又不污染生产核心源码。

## 4. 分波次执行顺序

**前置条件**：待 **2026-11-23 09:00** 首个自然定时日报在正式环境（`offline-v2-04`）运行并核对无异常后，再开新分支执行本清理，避免把首个自然窗口观测与代码修改混杂。

1. **Wave 1 — 清除零争议死代码与 `office_worker_path` 假路径**
   - 移除 `SessionRestartCounts`、`MAX_SOURCE_FILES_PER_RUN`、`AdapterPaths`（替换为 `pdf_worker_path`）、`ContextProfile` 的 7 个只写死字段与 6 个未调用 `Validate` 实现；移除 `AppConfig.office_worker_path` 字段但保留 `config.rs` 加载阶段对旧配置键 `scanner.office_worker_path` 的兼容读取。
   - 每步通过 `cargo test --manifest-path rust/Cargo.toml --workspace --locked`。
2. **Wave 2 — 精简 `doctor` 进程内返回值**
   - 用进程内 `ScannerDoctorReport` 替换 `DoctorResponse`、`DoctorCheck`、`DoctorCheckStatus` 与 `ScannerOperation<T>` 外壳；保留 `doctor --strict` 顶层字段和 `scanner.status` / `scanner.checks`（`scan_cache_v4`、`office_parser`、`pdf_worker`）。
   - 核对 `rust/daily_report/tests/operations.rs`、`bundle_acceptance.rs` 与 `scripts/release_common.ps1`。
3. **Wave 3 — 解耦 `ScanResult` 与旧 `ContextEnvelope` / `ScannerEvidence`**
   - 重写 `scan/evidence.rs` 为精简 `ScanResult` + `ScanStats`；扁平化 `ScannedFile`；停止拼接生产不消费的 180,000 字 `file_context` 字符串；同步更新 `run/input.rs` 与 `run/personal_scan.rs`；拆除 `provenance.rs`、`context.rs`、`envelope.rs` 中的冗余类型（将 `SourceGuardKind` 迁至 `pdf_wire.rs` 或 `contract/mod.rs`）。
   - 同步验证 `snapshot_key` 与 `config.fingerprint()` 在 `ScannerSettings` 序列化上无任何漂移。
4. **Wave 4 — 对齐测试与基准驱动**
   - 将 `rust/daily_parsers/tests/unit/settings.rs`（341 行）及 `tests/settings_fixtures/` 中仅覆盖旧 v1 跨进程信封的测试，收敛为聚焦 `ScannerSettings`、`PdfPageAudit` 与归一化规则的精简测试。
   - 将 `rust/daily_report/examples/kernel_v2_bench.rs` 与 `corpus_performance.rs` 适配 `ScanResult`（若需继续复用 `.artifacts/kernel-v2-20261122/bench/v2_evidence.py`，则在 `examples/` 内部完成投影，不留生产包内）。
   - 更新 `rust/daily_report/tests/personal_scan.rs`（第 454–461 行）与 `scan/tests.rs` 对 `execution_metrics` / `envelope` 的旧引用为 `ScanResult` / `ScanStats` 断言。
