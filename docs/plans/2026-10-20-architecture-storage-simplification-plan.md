# 架构与存储精简计划

日期：2026-10-20，Asia/Shanghai。

状态：实施中。用户已要求按计划执行，本地实现、隔离验证、历史文件去重和构建缓存复用正在进行。空间基线来自同日 00:38–00:44 的只读检查；实际进展见[实施结果](2026-10-20-architecture-storage-simplification-results.md)。

## 目标与推荐方案

保留现有解析、报告生成、恢复和发布能力，通过历史材料去重、解析身份拆分、构建缓存复用及快照容量统计优化，减少磁盘占用和重复工作。

完成标准同时覆盖空间、运行速度、开发速度、内容质量与恢复能力。空间下降需要实测；性能在同一机器、同一材料和同一资源配置下对照验证。不能用减少解析内容、减少校验或降低并发换取空间。

| 工作项 | 预期作用 | 收益口径 |
| --- | --- | --- |
| 历史材料去重 | 相同历史内容只保留一份底层文件数据 | 已确认重复内容上限约 15.88 GB，实际可回收量由用途和元数据筛选决定 |
| 解析身份拆分 | 编排和构建配置变化不再无故触发全文重解析 | 以缓存复用、重复解析数和新增存储量验收 |
| 构建缓存复用 | 保留常用缓存，收敛每次实验生成的独立构建目录 | 按失效缓存白名单实测；5.71 GB 调试符号不计为可全部回收 |
| 快照容量统计优化 | 一次写入会话只统计一次目录容量 | 以目录遍历次数、快照写入耗时和容量限制验收 |

Office Worker（独立解析进程）对扫描核心的依赖整理，放在解析身份工作中完成必要的最小调整；不以增加框架或拆分更多进程作为目标。

GB、MB 均为十进制。文件数据使用 `GetCompressedFileSizeW` 测量，再按卷和文件身份去重；不含全部文件系统元数据。跨目录硬链接共享数据另计，各目录独占值不等于整个目录的可删除大小。

本次重复核验覆盖两个历史目录下的四棵文件树，共 10,855 个独立文件，逐文件计算 SHA-256，读取错误为零。21,383,017,965 B 数据对应 3,050 组不同内容；冗余文件身份 7,805 个，内容去重上限 15,883,986,569 B。该上限尚未扣除写入用途、元数据差异和恢复依赖。

四个正式任务当前使用 `rust-20261019-reliability-01` 主程序。日报配置仍引用 `rust-20261018-release-03` 的解析程序，采集配置仍引用 `rust-20261017-archive-02` 的解析程序。实施前必须重新核对这些引用。

本节汇总不作为文件替换或删除清单。执行时生成逐文件冻结清单，记录当时的内容、身份、引用和实际占用。

### 1. 固定比较基线

实施前记录源码提交、工作区差异、实际任务入口、配置指纹、Worker及 PDFium 哈希、解析身份和发布包清单。保留用户已有文档改动。

对空间使用统一口径，区分逻辑大小、实际文件数据、同目录共享和跨目录共享。记录每个候选文件全部硬链接是否都位于允许范围；范围外仍有引用的部分不计入可释放量。

性能使用当前正式发布包作为基线，读取现有冻结材料，在隔离配置和独立数据库中执行。固定语料覆盖原有 2,648 文件基准，并补齐后来新增文件与现有支持格式的代表性样本。不得只比较成功或较小的文件。

交付：逐文件清单、保护清单、运行依赖表、原始性能记录和内容签名。

### 2. 历史材料去重

候选根目录精确限定为：

```text
D:\python_program\ai_daily_report\.artifacts\rust-migration\archive-benchmark-final-20261017\incremental\work
D:\python_program\ai_daily_report\.artifacts\rust-migration\archive-benchmark-final-20261017\incremental\data\archive\objects
D:\python_program\ai_daily_report\.artifacts\rust-migration\archive-benchmark-final-20261017-04\incremental\work
D:\python_program\ai_daily_report\.artifacts\rust-migration\archive-benchmark-final-20261017-04\incremental\data\archive\objects
```

采用同卷硬链接：多个历史路径共享同一份文件数据，路径和内容仍可直接读取。每组保留一个规范文件，不新增存储服务。

准入条件：

1. 文件属于已完成、已冻结的历史实验；没有运行中任务、写入者或后续原地修改用途。
2. 大小和完整 SHA-256 一致；替换前再次核对身份、大小、修改时间与内容。
3. 需要保持的时间戳、属性和权限兼容。具有重解析点、额外数据流、特殊属性或不可兼容元数据的文件跳过。
4. 所有关联恢复、压缩及验收工具允许文件身份变化。依赖原文件身份、链接数或独立备份的对象跳过；独立备份继续独立保存。
5. 历史输入的写入入口已经受控。新测试在独立目录生成可写副本，历史冻结目录拒绝直接复跑写入。只读文件属性作为辅助保护。

实现范围拟为 `scripts/deduplicate_historical_artifacts.py`、对应隔离测试及 `scripts/benchmark_archive.py` 的冻结目录检查。复用已有维护脚本的路径和文件核验方法；保留已冻结压缩工具的原字节及回退契约。

工具提供清单生成、预检、执行、独立核验和恢复操作。执行必须绑定清单哈希；支持中断续作和重复执行。每次替换先保存持久化操作记录，在同目录准备临时链接并验证，再使用原子替换。未完成该文件的核验前，不处理下一项。

恢复时从保留内容生成独立文件，恢复清单中的必要元数据。恢复文件身份会变化，必须明确登记；无法容许这一变化的对象不进入去重清单。提前计算恢复所需空间并验证隔离恢复，不能把“有另一条硬链接”视为独立备份。

完成条件：合格文件内容全部一致，清单和历史证据可读；重复执行无新增变化；模拟写入只影响独立工作副本；中断、占用、磁盘不足和恢复路径通过验证。真实收益扣除新增清单与操作日志。

### 3. 拆分解析身份并整理必要依赖

目前 [构建身份生成](../../rust/scanner_core/build.rs)包含整个扫描核心、工作区 `Cargo.toml` 和 `Cargo.lock`。[归档解析配置身份](../../rust/report_app/src/archive/parse.rs)及[扫描缓存身份](../../rust/scanner_core/src/store/cache.rs)又依赖该构建身份。

因此，本项必须先于构建配置调整完成。

设计要求：

1. 完整构建身份继续用于程序审计和 Worker握手。增加独立的解析内容身份，供解析缓存判断兼容性；不能把完整身份的校验直接删除。
2. 解析身份包含真正参与解析的源码、格式后端、协议、相关依赖版本及功能开关、PDFium 固定版本，以及影响输出的超时、容量和解析参数。影响条件编译与解析行为的构建输入也纳入。
3. 扫描编排、无关业务模块、文档及纯调试符号设置不参与解析内容身份。通过显式输入清单和反向变更测试证明边界，不能凭文件名简单排除。
4. 新程序保持 v4 握手兼容。解析内容身份由构建清单提供，并绑定实际 Worker完整身份和文件哈希；不向旧 Worker发送未支持字段。
5. 旧解析配置身份通过受限兼容表读取。每个映射绑定旧构建、实际 Worker、格式后端、完整参数和等价性证据；未知组合按缓存未命中处理。旧冻结输入、旧记录和旧文件保持原值，禁止覆盖原身份或使用通配映射。
6. 扫描缓存中的 `route_stack`、`worker_build` 等身份参与点一并处理，确保非解析改动不会从另一条比较路径再次使缓存失效。新写入记录仍保存真实程序与 Worker身份。

Office Worker目前通过 [文本归档入口](../../rust/office_parser/src/main.rs)调用扫描核心中的 `parse_archive_text`。将必要的共享文本解析代码集中到一个无调度、无数据库依赖的内部解析组件，扫描与 Office Worker共同使用；控制在这一真实依赖边界内，保留单一算法实现。

必须验证两组相反情况：只改调度、日志、文档或调试信息时解析身份稳定；改变解析算法、依赖、协议、预算或后端时身份改变。旧 Worker身份不匹配、内容损坏和未知兼容映射仍须拒绝复用。

完成条件：固定语料的正文、定位单元和内容签名一致；原有完整、部分提取和失败状态如实保持；隔离复制的现有归档在兼容升级后没有无故新增全文解析。已有冻结运行可继续恢复，旧程序可读取其原有证据。

### 4. 收敛构建产物

完整调试能力纳入质量要求。默认保留现有完整调试信息、增量编译、测试断言和发布优化参数，不把降低调试信息列为本方案的无损收益。

保留一套日常开发缓存和一套 Windows 正式发布构建缓存。正式发布继续使用现有 [构建脚本](../../scripts/build_windows_release.ps1)的隔离目标目录；收敛无必要的逐实验 `TargetDirectory`，各次发布只单独保存最终程序包、构建清单、源码差异及验收结果。

共享缓存的使用条件是目标平台、编译器、构建模式和参数匹配。让 Cargo判断复用；发布清单、Worker身份和独立包验收负责确认最终产物。发布包不得直接从过期文件位置拼装。

旧实验缓存逐项核对活动进程、正式配置引用、恢复依赖和是否可再生。被引用的 Worker、原生扩展、PDFium 和恢复材料保留。只将已被当前缓存替代、且无活动引用的文件列入清理清单；清理范围不能直接写成整个 `rust/target`。

当前 5.71 GB `.pdb` 为占用事实。减少调试信息会影响局部变量等调试能力，本计划不据此承诺等额节省，也不新增一套长期并存的轻量缓存。

完成条件：相同改动的增量编译耗时不退步；正式包功能、大小和运行性能符合基线；能继续进行完整调试；空间按去重后的实际清理结果记录。恢复历史失效缓存需要重新编译，其耗时与正常开发编译分开说明。

### 5. 优化快照容量统计

[快照写入](../../rust/report_app/src/snapshots.rs)当前每次新写入都调用 `total_bytes()` 遍历整个目录。保持路径、原始字节、哈希、单文件上限、总容量上限和不可变写入行为。

采用一次持锁写入会话内累计容量的方式，不新增持久化容量数据库：

1. 核对日报、周月报、恢复、维护及旧 Python工具对同一快照根目录的所有写入入口。只有能证明它们受同一报告库与作用域的 `ReportLock` 保护时，才启用会话计数。
2. 调用方取得现有报告锁后显式开启写入会话，并扫描一次现有容量；不能在 `App::open` 中无锁缓存一个可能过期的值。复用现有锁，不额外用长时间根目录锁串行化原本独立的任务。
3. 同一会话中的并发模型批次共享容量计数和现有进程内互斥。写入前预留容量，成功后确认；失败时撤销预留，同一内容命中不重复扣减。
4. 清理与维护通过同一互斥范围更新或使计数失效。会话结束后丢弃计数；崩溃后的新会话重新统计。孤立临时文件继续计入实际占用，沿用明确的恢复处理。
5. 多作用域共享根目录、独立 `SnapshotStore` 调用及无法证明互斥的旧入口，保留原有逐次统计行为。只读入口保持独立，旧恢复工具继续可用。

完成条件：符合互斥条件的批量写入每个会话只全量统计一次；多进程、并发批次、重复内容、容量临界、磁盘写满、写入失败、崩溃恢复及清理交错通过检查，不引入新的超额或误删，读回字节与原哈希一致。无法证明并发正确性的路径不启用优化，也不宣称它已解决既有跨作用域竞争问题。

## 四、统一验收

| 维度 | 验收要求 |
| --- | --- |
| 空间 | 同一允许范围前后盘点，扣除共享数据和新增证据；每项收益独立计算，避免重复相加 |
| 原始内容 | 去重候选文件逐项完整哈希一致；正式原件、解析内容和冻结证据无意外变化 |
| 提取质量 | 固定语料逐文件比较正文、定位单元、引用和状态；失败、部分提取及覆盖缺口不得隐去 |
| 报告质量 | 使用保存的响应和本地模型替身重放；事实、引用、待确认及正文一致，仅预先声明的运行元数据允许变化 |
| 无变化采集 | 连续 20 轮，P95 不退步且不高于 5 秒；源正文读取、解析启动及模型调用为零 |
| 冷解析与变化采集 | 同一语料、配置和资源预算比较耗时、CPU、进程树峰值内存及磁盘读写；覆盖全部支持格式 |
| 快照 | 批量写入遍历次数达到设计目标；容量与不可变性检查保持；并发及失败路径通过 |
| 开发速度 | 相同小改动的增量构建耗时不退步，完整调试能力可用 |
| 恢复 | 隔离完成文件去重恢复、旧冻结运行恢复和旧包读回；实际回退不能仅依据命令存在判定通过 |

P95 指 95% 的运行不超过的耗时。测试先固定基线波动范围，再用交替对照测量。超过正常波动的性能退步判定失败；波动太大无法判断时，性能验收保持未通过，不能以“基本一样”替代证据。

计时期间不并行构建、测试、内容哈希扫描或真实采集。记录应用缓存与操作系统文件缓存状态；不主动清空系统缓存，也不把文件缓存已热的测量标为真正磁盘冷读。

保留原有 Windows 运维与健康脚本检查。源码整合后的 Rust 门禁：

```powershell
cargo fmt --manifest-path rust/Cargo.toml --all -- --check
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --locked -- -D warnings
cargo test --manifest-path rust/Cargo.toml --workspace --locked
```

集成测试前按项目要求构建匹配的 debug Worker与 examples，准备固定 PDFium。正式包用 `scripts/build_windows_release.ps1` 同批构建三个可执行文件，完成清单、自检和独立无 Python验收。模型重放使用隔离材料，不新增真实模型调用。

## 五、执行授权与回退

用户已要求按计划执行。本地源码实现、隔离验证和明确目录内的历史去重沿用该授权；正式配置切换与发布仍遵守项目的独立授权边界。工具策略阻止的操作保持未执行，并在实施结果中单独记录。

执行历史文件替换或缓存删除前，提供精确绝对路径、实际可回收量、影响及恢复所需空间。去重失败时按持久化操作记录恢复；每次恢复都重新核对内容与必要元数据。

正式切换准备使用新目录的完整发布包，并保存当前任务 XML、配置相关段、包清单和一致数据库备份。四个任务及主配置、采集配置中的实际 Worker路径一起核对；保留各任务原有时间窗口和资源参数。

上线仅在授权后进行。切换后验证任务回读、严格自检、健康状态和历史报告哈希；不主动触发付费报告。人工或隔离验证与下一次真实日历触发分开记录。

程序回退恢复旧任务与配置引用，保留新增业务记录，不用旧数据库备份覆盖新数据。旧解析身份、旧包和旧 Worker继续保留到其既有清理条件满足且获得明确清理授权。

## 六、交付与完成判定

交付源码及定向测试、历史去重工具、冻结清单、恢复记录、前后空间统计、性能对照、内容签名和最终发布包。业务原件及模型原始材料保留在本机证据目录，不进入 Git或对外文档。

完成报告区分：

- 已实现并通过隔离验证的代码。
- 已执行的历史去重及失效缓存清理，以及实测净释放空间。
- 已上线的程序、实际引用路径和回读结果。
- 已发生的真实定时验收，以及仍待发生的日历触发。

若某类历史文件因元数据或恢复约束不能去重，保留并列明原因，实际收益据实减少。若代码调整导致性能、内容或恢复能力退步，该调整不进入正式发布。
