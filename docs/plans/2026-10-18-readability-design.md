# 日报可读性设计（子项目 B）

- 状态：已实现，待用户验收（c126bd5）
- 日期：2026-10-18
- 范围：日报正文的呈现层与提示词层可读性；不含报告格式版本（v4/v5）、数据库结构、扫描/解析范围、模型选择与成本策略
- 关联：[当前状态](../current-state.md)、[定时链路可靠性设计](2026-10-17-scheduled-reliability-design.md)、[日报使用与恢复](../daily-report-operations.md)

## 一、背景与证据

以最近一份真实日报 `data/reports/2026-10/2026-10-16.md`（v3 结构，21,263 字符，397 行）为样本，并用报告库 `daily_reports.raw_json` 交叉核对：

| 现象 | 证据 |
| --- | --- |
| 事项碎片化 | 42 个事项、75 个详情段；每个事项平均不到 2 段，读者难以判断主次 |
| 事项标题偏文件名 | 如「2026年上半年部门处理明细（部分流程）」「供应链相关表单目录与审批流梳理」，不是业务结论 |
| 数字密度高 | 75 段共 743 个数字记号，平均每段 9.9 个；31 段含 ≥8 个数字，单段最多 56 个 |
| Markdown 转义噪音 | 89 处反斜杠转义：`\(`/`\)` 各 29、`\*` 8、`\+` 7、`\[`/`\]` 各 6、`\#` 3、`\_` 4 |
| 覆盖缺口重复展开 | 「来源与覆盖附录」18 条缺口只对应 4 个错误码；`PARSE_BOUNDED` 一行一个来源重复 11 次，`EXCERPT_BOUNDED` 重复 5 次 |
| 待确认无分组 | 15 条待确认中至少 6 条是「表头/字段为空」类技术缺失，与业务待确认混排；「波锋权限指引表」相邻两档重复两条 |
| 缺少概览数据 | 读者不知道当天读了几份材料、成功几份、有多少确定/待确认事实、缺口几类 |
| 无导航 | 42 个事项无目录、无锚点，长报告只能顺序滚动 |
| 概览被单一主题占满 | 5 条概览全部是 OA 审批相关内容，供应链与产品试用类事项没有进入概览 |

v4（归档来源，计划版本 5）在 v3 结构之后追加「变化依据」审计附录（每条事实的版本、位置、原文引用和 SHA-256）。该附录尚未有真实生产样本：首份定时 v4 日报在 2026-10-18 09:00 由现有发布包生成，不属于本设计范围内可改动的对象。本设计不改变审计附录结构，只在其之前改善正文可读性；附录体量问题列入 B3 观察项（见第九节）。

## 二、目标与非目标

**目标**

1. 30 秒把握要点：标题下新增确定性统计行；「内容概览」保持 ≤5 条、一句一条。
2. 3 分钟读完正文：事项标题业务化、长段按句切分、每段数字密度受控；42 个事项可经目录跳转。
3. 清除噪音：转义最小化；覆盖缺口按错误码聚合；重复详情去重。
4. 不牺牲审计：来源标签、引用、SHA-256、覆盖缺口、质量标记、`变化依据` 全部保留，只改呈现方式。
5. 改进全部由仓库内代码与模板完成，可由离线 fixture 验证；不新增模型调用。

**非目标**

- 不新增第二次模型调用（不加「管理层摘要」生成步骤），不引入新的模型或预算。
- 不改报告 schema 版本、模型计划版本、数据库结构；不改历史报告正文，不重跑模型。
- 不改扫描、解析、OCR、采集范围与频率。
- 不改审计附录「变化依据」的结构（B3 单独决定是否调整）。
- 不把技术统计移出报告文件；报告仍自包含。

## 三、总体方案（已选）

三层处理，优先级从确定性到模型：

1. **渲染层（确定性）**：转义收敛、速览统计、缺口聚合、长段切分、事项目录、重复段去重。全部可用离线 fixture 断言。
2. **提示词层（模型，受约束）**：compose/facts 提示词补充长度、数字密度、标题、去重要求；不新增硬校验上限，避免把风格问题变成 `MODEL_RESPONSE_INVALID` 失败。
3. **审计层（不变）**：附录、引用、哈希、缺口原因保持完整；只把重复的同一错误码合并成一行。

备选方案与取舍：

- 只改提示词：模型输出风格不可控，且无法修复转义与缺口重复，不采用。
- 只改渲染层：无法降低数字密度和标题噪音，不采用。
- 增加一次「摘要」模型调用：成本与失败面增加，且可靠性子项目刚引入重试与降级，不叠加，不采用。
- 报告拆成「正文 + 审计附件」两个文件：改变交付契约与验收口径，暂不采用。

## 四、详细设计

### B1 转义最小化（`evidence_text`）

- 位置：`report_app/src/reports.rs::evidence_text`。
- 现状：对 `\` `` ` `` `*` `_` `{}` `[]` `()` `#` `+` `!` `|` `>` 一律反斜杠转义，产生 `\+38909%`、`\(新\)`、`\[集团\]`、`\#N/A`。
- 新规则：先把 `& < >` 实体化；再只对 `\` `` ` `` `*` `_` `|` 反斜杠转义；仅当 `#` 位于文本行首时转义。`+ ( ) [ ] { } !` 不再转义。
- 方括号的取舍：单独的 `[集团]` 不构成 Markdown 链接，转义后反而成为可见噪音（真实日报 89 处转义中 `[`/`]` 占 12 处），因此不再转义。残留风险是材料原文出现 `[文字](链接)` 时会被渲染成链接；本报告只处理本地材料，且引用链接由程序单独生成，接受该风险并记录在第七节。
- 文本换行仍折叠为空格，不产生新的行首。
- 测试：保留 `**重点**` 断言；新增 `(新)`、`+38909%`、`#N/A`（行中）、行首 `#`、`{x}!`、`[集团]` 用例。

### B2 速览统计行

- 位置：两个日报模板标题之下、`## 内容概览` 之前；数据由 `render_daily` 注入派生字段。
- 内容（一行或两行）：
  - `本报告基于 {{sources_total}} 份材料（读取成功 {{sources_usable}}、失败 {{sources_failed}}），提取事实 {{facts_total}} 条（确定 {{facts_confirmed}}、待确认 {{facts_pending}}）。`
  - 有缺口时追加：`覆盖缺口 {{gaps_codes}} 类共 {{gaps_total}} 项。`
- 边界：`quality == no_changes` 不显示统计行（沿用「未发现修改」语义）；`content` 为空时仍显示材料统计，并沿用「暂不扩写」说明。
- 统计只依赖已校验字段，不新增数据来源。

### B3 覆盖缺口按错误码聚合

- 位置：渲染前派生 `gaps_grouped`（不改 `DailyReport` 结构与校验）。
- 规则：按 `code` 首次出现顺序分组；同组只输出一行，消息取组内首条，来源标签合并为 `S002、S005、S006`；无来源的条目单独保留。组内来源超过 6 个时用 `S002 等 11 个来源`。
- 预期：18 条 → 4 条；`PARSE_BOUNDED` 一行列出全部来源。

### B4 长段按句切分

- 位置：渲染层派生 `paragraphs`（事项 `background`/`details`），不用于 `overview`/`pending` 列表项。
- 规则：文本超过 240 字时，在 `。`、`；` 之后切分，向均衡分段靠近，最多 3 段；不足 240 字不切。切分只插入段落空行，不增删字符；引用标记仍跟在最后一段之后。
- 目的：把 500–600 字的连续叙述拆成可扫读的 2–3 段，不改变事实与引用。

### B5 事项目录

- 条件：`content.matters` 数量 ≥ 10 时输出；否则不输出。
- 结构：`## 事项目录` + 每行 `- [标题](#m<N>)`；每个事项标题前插入 `<a id="m<N>"></a>`。
- 标题已在 `ComposedReport::validate` 中保证唯一（matter_id 或标题），锚点用序号避免中文转义差异。

### B6 提示词约束

- compose（v4）：每条 detail ≤3 句且 ≤200 字；每事项 details ≤4 条；每段最多保留 3 个关键数字，其余用「多档」「大幅」等概括且不得改动数字本身；标题 8–24 字，概括业务事项，不使用文件名/表名/「部分流程」；同一事项的现状与建议方案放同一事项；技术性缺失（表头为空、字段缺失）合并为一条待确认，除非影响结论。
- facts（v4）：topic ≤24 字；detail ≤600 字；conditions ≤6 条；同样精简数字。
- 不新增硬校验上限；现有 `bounded(text, 4000)` 等上限不变。风格不达标不导致整日失败。

### B7 文档与示例

- README「日报按…呈现」一段补充速览、目录、缺口聚合说明。
- `docs/daily-report-operations.md` 增加「报告结构」小节与「可读性变更不改变审计信息」说明。
- 示例配置不变。

## 五、错误处理与边界

| 场景 | 处理 |
| --- | --- |
| `quality == no_changes` | 不显示统计行与目录；沿用「未发现修改」正文 |
| `content` 为空但材料可用 | 显示材料统计；沿用「暂不扩写工作进展」 |
| 缺口无来源 | 单独一行，不参与来源合并 |
| 事项 < 10 | 不输出目录与锚点 |
| 段落无句末标点 | 不切分，保持原文 |
| 转义规则变化影响历史 fixture | 只影响新渲染；历史正文存于数据库，不重新渲染 |
| 提示词变更 | 改变请求身份，属于新发布的预期变化；部署时按现有流程 `doctor --check-model` |

3. 渲染正文断言：`\+`、`\(`、行中 `\#` 噪音为 0，行首 `#` 仍转义；缺口行数等于错误码数。
4. 提示词：`operations.rs` 打包字节校验保持通过；如测试断言提示词指纹，按变更更新并说明。
5. 全量 `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo test --workspace --locked`。
6. 不调用真实模型；不以真实日报发布作为本子项验收前提。

## 七、风险与已定决策

| 风险 | 处理 |
| --- | --- |
| 转义收敛导致渲染器把内容当 Markdown | 仍转义 `\` `` ` `` `*` `_` `|`，`#` 只在行首转义；方括号不转义，单独 `[文字]` 不构成链接 |
| 材料原文含 `[文字](链接)` 被渲染成链接 | 只影响链接外观，不改变文字与引用；本报告只处理本地材料，接受该风险 |
| 段落切分改变引用位置 | 引用仍在该事项段尾；切分不改字符顺序 |
| 提示词约束降低事实完整度 | 只约束表达，不减少 fact_ids 覆盖；校验仍要求覆盖全部输入事实 |
| 模板改动影响正在进行的 10-18 验收 | 本子项只在仓库内开发；生产仍用 `rust-20261017-archive-05`，验收完成前不部署 |
| 审计附录「变化依据」体量过大 | 本设计不改结构；B3 用首份真实 v4 日报测量后再定 |
| 历史报告被重渲染 | 修复输出读取数据库正文，不重渲染；冻结输入自带模板字节 |

已定决策：

- 结构改进同时作用于 v3 与 v4 模板，保持同一份报告语言；v4 的「变化依据」保持原样。
- 不加硬性长度校验，只做提示词约束与渲染层切分，避免可读性问题变成运行失败。
- 目录仅在事项 ≥10 时出现，避免短报告冗余。
