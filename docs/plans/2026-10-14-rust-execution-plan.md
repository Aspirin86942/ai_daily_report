# AI Daily Report Rust 统一实现执行计划

日期：2026 年 10 月 14 日\
更新日期：2026 年 10 月 15 日\
依据：[产品计划书](2026-10-14-rust-product-plan.md)\
代码基线：`069045f`，实施前重新核对当前提交与工作区改动。

完成一个不依赖 Python 的 Windows 报告程序，保留已确认的报告、数据和恢复能力，并使日报按事项讲清具体内容、关键条件与当前状态。实现采用两个新增 Rust 工程包、每种格式一条解析路径、一处模型重试逻辑；复用现有扫描核心和 Windows 解析进程管理。

本计划给出具体修改范围、任务顺序和验证命令。2026 年 10 月 15 日开始执行；新增目录、接口及测试以任务状态和验证证据区分已完成与待实现。

## 一 实现约束

### 简化规则

| 事项 | 固定做法 |
| --- | --- |
| 工程拆分 | 新增 `report_app` 和 `pdf_parser` 两个工程包。报告业务与命令行放在同一工程包的库和可执行入口中 |
| 业务组织 | 使用普通模块、结构体、枚举和函数；不引入插件系统、依赖注入容器、通用工作流引擎或多层服务转发 |
| 文档解析 | 依据真实格式选择一个解析器。失败后记录错误与覆盖限制，继续处理其他文件，不轮流尝试备用引擎 |
| 模型通信 | 一个 HTTP 客户端、一处重试循环；不自动更换模型、服务商或请求格式 |
| 日报成稿 | 完整分批提取事实，容量允许时一次成稿，否则按主题分组成稿并由 Rust 合并；沿用同一调用与恢复代码，不增加评分、润色循环或专用工作流框架 |
| 输入校验 | 在配置加载、外部响应和磁盘证据读取边界校验；内部已经验证的类型直接传递 |
| 版本支持 | 当前报告库、当前扫描库和基线实际使用的快照格式有明确支持范围；未知版本明确拒绝，不猜测或自动修补 |
| 代码迁移 | 直接复用现有 Rust 模块，将 Python 业务迁入新模块；完成对照验证后移除旧生产路径，不长期保留双实现 |
| 运维工具 | 任务安装、检查和删除继续复用现有 PowerShell 脚本；Rust 提供任务计划数据，避免再造 Windows 任务管理封装 |

### 必须保留的保护

- 报告数据库事务、单实例锁，以及先提交数据库再发布文件的顺序。
- 输入与模型响应快照、原字节哈希、成功响应复用及外部编辑检测。
- 已发生调用和未知调用的记录；恢复不能清零消耗或伪造成功。
- 文件解析的截止时间、内存限制和进程隔离；单个解析器故障不破坏报告数据库。
- 当前配置的请求限制、重试上限、覆盖审计和质量标识。

这些保护直接服务于数据正确性和可恢复性，不扩展成自动修复框架。

### 格式范围与旧实现移除条件

保留文本、CSV、JSON、日志、XLSX、真实 XLS、DOCX、PPTX、PDF，以及现有显式启用的 `.doc`、`.ppt` 解析能力。旧版 DOC/PPT 延续默认关闭；保留扩展名错误但真实内容属于支持格式的文件识别。

用户已确认：旧格式能力被替代后允许移除旧实现。移除条件是同一批真实二进制 DOC/PPT 样本通过 Rust 路径验证，必要文字、输出限制及错误处理满足既有要求，并确认扫描链不再调用对应 Python 解析器。满足条件后移除对应旧实现和专属依赖，保留 DOC/PPT 文件支持；每种格式只保留一条解析路径。

2026 年 10 月 15 日实施前核对：扫描路由使用 `python_sharepoint_text_v2`，Rust 工作进程尚未接通 DOC/PPT。T05 已复用 `office_oxide 0.1.2` 完成真实 DOC/PPT 接入，并验证必要文字、范围、限制及错误处理；新 Rust 扫描链已移除 Python 路由。旧生产程序源码及专属依赖在整套程序对照通过、T12 正式切换及旧版归档完成后统一移除。

### 日报内容改进依据

2026 年 10 月 15 日对 2026-04-12 至 2026-10-11 的 183 份历史日报做结构统计：117 份证据格式日报有摘要，64 份记录未发现目标日期内修改的文件，另有 2 份早期工作日志格式。117 份有摘要日报中，摘要正文字符合计占全文约 33%，摘要条数中位数为 17。抽读发现主题散落、相同事实重复、术语未解释和业务背景不足；部分日期同时存在实际材料覆盖不足。10 月 13 日日报仍有 48 条平铺摘要，说明主题组织也需要明确的产品要求。

当前 `evidence_summary_prompt.md` 和响应类型限制每批 6 条、每条 180 字，`model_plan.py::merge_summaries` 只对“完全相同的文字与来源集合”去重。当前规则用于定位改进位置，不据此推断所有历史报告都使用了相同提示词版本。

执行目标为产品计划书中的“内容概览、按事项展开、待确认、来源附录”。T06 完成事实提取、按容量成稿和完整合并，T07 完成内容组织与模板。历史正文继续保留，自动化验证使用合成或脱敏样本；经授权的真实材料验收只在隔离目录运行。

| 内容要求 | 执行位置 | 验收结果 |
| --- | --- | --- |
| 同一事项集中呈现、重复事实合并 | T06 成稿与 T07 模板 | 跨文件、跨批次的同一事项归并；不同主体、期间与版本仍可区分 |
| 关键细节与术语解释充分 | T06 事实条目与成稿 | 必要背景、数据含义、适用条件、例外和状态完整，术语首次出现有简短说明 |
| 正文易读、证据可查 | T07 模板 | 概览在前、事项展开在后，引用紧邻事实，技术明细集中在附录 |
| 内容不足如实呈现、历史正文可恢复 | T04 存储与 T07 发布 | 缺少材料时明确缺口，方案不写成已完成；历史修复保持原正文与哈希 |

## 二 目标结构与接口

### 工程结构

```text
rust/
  report_app/       # 新增：包名 ai-daily-report，包含 lib.rs 与 main.rs
  pdf_parser/       # 新增：包名 ai-daily-pdf-parser，独立解析进程
  scanner_core/    # 复用：扫描、预算、缓存、上下文及进程调度
  scanner_contract/ # 复用：扫描领域类型
  worker_contract/ # 复用：同版解析进程协议
  office_parser/   # 复用：Office 解析，补齐 XLS 与已有成功案例
  discovery/       # 复用：文件发现
```

`report_app` 按 `config`、`types`、`run`、`store`、`snapshots`、`model`、`reports`、`publish`、`maintenance` 组织普通模块。内容较多的模块可以拆成模块目录，保持同一工程包。

业务入口采用 `run_report(request, app) -> Result<ReportOutcome, ReportError>`。`App` 直接持有配置、报告存储及模型客户端；`ReportRequest` 区分日报、周报和月报，`RunPhase` 表达既有运行阶段。

只为网络测试替身保留一个小型 `ModelTransport` 接口。数据库测试使用临时 SQLite，扫描直接调用现有 Rust 接口；业务时间作为输入传入，避免为每项依赖建立接口与工厂。

### 命令入口

| 入口 | 约定 |
| --- | --- |
| `daily`、`weekly`、`monthly` | 保留现有日期、来源、预览和重新生成参数语义 |
| `list`、`runs`、`repair-output`、`doctor` | 保留查询、自检、修复及已有别名；修复输出不调用模型 |
| `backfill` | 承接补跑脚本的日期、预检、并发、OCR 清单与筛选参数 |
| `coverage plan / generate / publish / recover / amend` | 分别对应固定输入、生成候选、发布、部分成功恢复和已确认失败的执行修订；复用同一业务函数 |
| `ocr validate --manifest` | 检查 OCR 清单、原文件身份及未核实文字标识；报告和补跑读取同一验证结果 |
| `task plan --sid` | 输出既有任务计划及 XML 数据，供 PowerShell 安装、检查、删除脚本使用 |
| 全局 `--config-dir` | 显式选择配置目录；省略时固定使用程序所在目录下的 `config`，不遍历目录猜测配置 |

现有 `coverage` 恢复中的预算修订、运行配置修订和授权说明作为对应命令的明确参数处理，直接调用迁入的函数，不增加隐藏恢复分支。历史脚本的每个生产选项在 T01 建立映射，迁移后以新命令说明更新调用方。

新增配置与包版本采用产品计划书已经选定的库。所有直接依赖和 PDFium 构建在 T02 固定版本，沿用现有 Rust edition；不同时进行无关工具链升级。

## 五 失败处理规则

| 失败位置 | 处理方式 | 重试边界 |
| --- | --- | --- |
| 配置、DLL 或协议版本不正确 | 返回明确错误，停止本次命令 | 不猜测路径，不临时下载，不切换旧实现 |
| 单文件无法解析或超时 | 记录该来源错误和覆盖限制，在总预算内处理其他文件 | 当前文件不自动换解析器；损坏进程只为后续任务重建 |
| 模型瞬时错误 | 同一重试循环按错误类别和剩余时间处理 | 沿用现有总尝试上限，默认最多三次 |
| 模型永久错误或校验失败 | 返回对应错误，保留已成功步骤供显式恢复 | 不换服务商，不猜测修正输出；容量不足按完整单元拆分并处理两部分，不丢弃剩余输入 |
| 模型结果保存失败 | 保留未知调用记录并停止 | 同一次错误处理中不重发请求 |
| 数据库失败或证据哈希不符 | 停止当前业务操作并记录错误码 | 不修补数据，不清空记录重新执行 |
| 数据库已提交但文件发布失败 | 保留待发布状态，由正常恢复或 `repair-output` 重放正文 | 零扫描、零模型调用 |
