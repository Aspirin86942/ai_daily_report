# 产品能力范围方案（子项目 F）

- 状态：待用户选择（尚未立项实现）
- 日期：2026-10-18
- 目的：给出可直接开工的能力选项、代价与推荐顺序，用户选定后再写设计与计划
- 关联：[当前状态](../current-state.md)、[日报使用与恢复](../daily-report-operations.md)、[工程清理设计](2026-10-18-engineering-cleanup-design.md)

## 一、现状与边界

当前产品能力：本地文件采集/归档、日报/周报/月报生成、补跑与恢复、覆盖修复、`runs`/`list`/`archive`/`stats` 查询、只读 `health` 巡检与 Windows 通知。输出为 Markdown 文件与数据库记录，单 `work_dir`、单 `scope_id`，无对外交付、无检索、无图形界面。

本轮（F）的既定边界：

- 仓库内开发与本地验证；不部署生产、不改正式任务与配置、不调用真实模型（除用户另行授权）。
- 优先零模型、离线可验证的能力；需要网络或凭据的选项必须单独授权。
- 不改变报告格式契约（v3/v4）、审计要素与已有数据；新增能力原则上使用新表/新命令，不改既有表结构。
- 保持 Windows x64、发布包不依赖 Python 的约束。

## 三、最可能落地的三个

### F1 历史检索（推荐先做）

- 做法：在报告库新增独立 FTS5 索引表（不改 `daily_reports` 结构），`daily`/`backfill`/`repair-output` 后增量更新；新增 `search --query --from --to --source --kind` 命令，输出命中日报、事项标题、摘录与来源标签。
- 验证：合成库测试 + 真实报告库只读重建；零模型。
- 边界：只读搜索，不修改报告；索引可重建；旧报告无索引时按需回填。

### F2 交付通道（最贴近日常使用，但需授权）

- 做法：新增 `notify` 能力，日报发布后读取已发布正文，生成 3–5 条摘要 + 本地路径/链接，通过企业微信机器人或 SMTP 发送；失败写入运行日志并复用健康巡检告警。
- 需要用户先定：渠道（企业微信机器人 / 邮件 / 仅本地通知）、凭据存放位置（`.secrets.yaml` 或环境变量）、外发内容范围（是否含原文摘录）。
- 边界：发送失败不影响报告发布；不在报告中写入凭据；可选开关默认关闭。

### F4 周月报增强（低风险增量）

- 做法：在现有周/月报聚合上增加确定性指标（日报数、来源数、确定/待确认事实数、缺口类别、Top 变化主题）与简单的文本/表格视图；不新增模型调用。

## 四、暂不建议

- **F3 PDF**：Windows 无 Python 的发布包需要一个内嵌渲染引擎，体积与许可成本高；可先用 HTML 导出配合浏览器打印替代。
- **F5 仪表盘**：符合“浏览历史”的需求，但会引入本地监听端口与页面维护成本；在 F1 检索稳定后再评估。
- **F6 多范围**：会改变报告范围、任务与锁的既有契约，影响回退验证；除非确有团队级需求，否则不建议现在做。

## 五、推荐顺序与理由

1. **F1 历史检索**：零模型、离线、可测试，直接补上“找不到上次结论”的痛点，对现有契约零影响。
2. **F2 交付通道**：需要你确认渠道与凭据后单独设计；它是“产品可用性”最大增量，但外发与凭据属于新边界。
3. **F4 周月报增强**：作为检索/交付之后的低风险增量。

## 六、需要你决定

1. F 先做哪一个：F1 检索、F2 交付、F4 周月报增强，还是其他？
2. 若选 F2：用企业微信群机器人、SMTP 邮件，还是只做 Windows 本地通知？凭据放 `.secrets.yaml` 还是环境变量？摘要是否允许包含原文摘录？
3. 是否有时间/范围约束（例如只做只读能力、暂不联网）？

选定后我再写 F 的设计与实现计划，并按 B/E 的方式实现与本地验证。

## 七、可行性核对（2026-10-18，只读）

- **FTS5 可用**：`rusqlite 0.40.1` 使用 `libsqlite3-sys 0.38.2` 的 bundled SQLite，构建脚本启用 `SQLITE_ENABLE_FTS5`（`build.rs` 中 `-DSQLITE_ENABLE_FTS5`），F1 无需新增依赖，也不需要网络。
- **报告库规模**：`data/db/reports.sqlite3` 37 MB，`daily_reports` 188 行、`raw_json` 合计 5.77 MB，周报/月报各 1 行。报告正文全部可索引，索引规模与报告库同量级。
- **归档库边界**：`data/archive/index.sqlite3` 75 MB，`documents` 2,686、`versions` 2,700、`extractions` 2,562；但 `extractions` 表不存正文（正文对象在磁盘上，`manifest_json` 只含哈希、字符数与覆盖信息）。归档全文检索需要读文件并另建索引，属于比“报告检索”更大的范围，建议 F1 先只覆盖报告库。
- **结论**：F1 的范围可先定为“报告库检索”（日报/周报/月报正文、事项标题、待确认），归档全文检索作为后续增量；两者都不调用模型、不改现有表结构。

## 八、F1 若被选中时的候选范围（供选择）

- 命令：`search --query <关键词> [--from YYYY-MM-DD] [--to YYYY-MM-DD] [--kind daily|weekly|monthly] [--source S001] [--format text|json]`。
- 范围：只读报告库；输出命中日期、报告类型、事项标题/片段与来源标签；`--format json` 供脚本消费。
- 索引：新增独立 FTS5 表，按报告 `(date, kind)` 增量重建；提供 `search --reindex` 或复用现有维护命令；不修改 `daily_reports` 等既有表。
- 验证：合成报告库单测（中文分词用 trigram 或 unicode61 + 前缀查询需实测）+ 真实库只读重建；零模型、零网络。
