# 个人日报内核二期实施与验收

二期交付一个候选包。源码基线为 `5e8c8e9236aea4691b3c8484b5055accde9c66ef`。当前正式包 `rust-20261121-kernel-once-01` 用于比较二期与现网的变化，历史包 `rust-20261121-detailed-daily-01` 用于复核原七项性能参考线。最终数值和通过情况由 `.artifacts/kernel-phase2-20261121/final-verification.json` 及其引用的原始记录给出。

## 实施顺序

1. 修复坏 PDF 的重复分类。仅复用解析器明确辨认的确定性文件错误，保留原错误码、来源、覆盖缺口及名义页数预算。命中时记录本次实际分类次数为零。文件校验信息、来源版本、页数窗口、规范化配置或解析身份改变后重新分类。瞬态错误仍按原规则执行。保持 Worker 协议 v4、既有数据库主表和历史记录可读。
2. 精简派生检索库。原始片段和位置有唯一归属。中文短词、同片段多词、精确空白、标题权重、同分顺序与附件定位分别对照。索引内容和版本在同一事务中发布。检验删除、替换、并发、建库失败恢复，以及旧索引升级后实际占用。同步写入策略仅调整派生库连接。
3. 保持 XLSX 单文件上限 52,428,800 字节，以有效的合成表格验证上限前一字节、等于上限、超过一字节三处边界及日报缺口。OCR 保持关闭。材料摘录保留首、中、末原文范围，表格保留整行、单位、否定条件和页码。
4. 根据调用关系先确定可删除实现，再按职责拆分 Office、存储、契约、调度、扫描执行和审计模块，同时处理其他超过上限的核心文件。保留存储终止写入、历史周月报读取、冻结输入回放及原字节恢复。各模块用相关测试、格式和静态检查锁定行为。结构调整的对照对象是证据、顺序、正文和附件；单独记录构建身份、缓存事件和运行耗时。
5. 保留离线历史维护、PDF 压测及其测试。受替换的验收脚本须先核对等价断言和失败退出。对一次性看板脚本归档并验证字节。原有恢复材料和运行数据继续保留。

全部验收使用隔离目录、固定语料、保存的答复或本机替身。真实模型请求数为零。验收报告记录候选包哈希、原始测量、失败项和复现入口，缺项不得判定通过。

检索实现共用一份展示片段及来源位置。普通查询和精确短语各有一套 FTS5 外部内容索引，只保存相应的检索数据。两种查询在 v5 的 BM25 评分中使用不同的片段长度，分开保留这两组统计可以逐条核对排序，也能保留精确空白和字段边界。升级时由派生库回收空页，以关闭连接后的实际文件大小验收。

## 正式切换条件

全部本地门槛通过并归档后，单独申请正式切换。切换前按 `docs/windows-deployment.md` 一致备份原包、配置、两项任务 XML 和两个数据库，校验哈希。正式切换的即时核验覆盖两项任务、解析程序身份、已发布正文与附件哈希、模型调用账本及相对基线的新增错误。切换基线已有一项历史错误和一项材料范围预警。
