## 运行条件

- 使用 `.python-version` 指定的 CPython 3.13.13 和项目 `.venv`。
- Python 依赖用 `uv sync --frozen` 安装；Rust 工作区按锁文件构建。
- 本机设置保存在 Git 忽略的 `config/settings.windows.yaml`。示例文件不含真实工作路径或凭据。
- 公司网关凭据从执行账户的 `DEEPSEEK_API_KEY` 读取。凭据不写入命令参数、任务 XML、报告或日志；已有通用配置中的其他服务凭据不会被用于公司网关。
- 通过网关控制台或正式文档确认 `llm.context_window_tokens` 和 `llm.verified_max_output_tokens` 后填写。空值时，含业务内容的模型请求会停止；本地预检和无需模型的空日报仍可执行。

本机已从认证的模型能力接口核实最大输入 1,000,000、最大输出 393,216 tokens。由于接口未单列合计窗口，程序保守地以 1,000,000 限制输入估算与输出预算之和。本机 `llm.max_tokens=8192`，包含模型思考和最终输出；真实材料在 2048 时曾因思考占满预算而截断。

本机配置读取顺序为 `settings.yaml`、当前系统的 `settings.windows.yaml`、`.secrets.yaml`，后加载的文件递归合并并覆盖同名标量字段。当前本机配置和示例在 `scanner` 下设置 `dynaconf_merge: false`，整节替换旧扫描配置，保证文件类型和排除列表按当前配置生效。移除这个标记后，Dynaconf 的全局合并会追加列表元素，见[官方合并规则](https://www.dynaconf.com/merging/)。`DAILY_REPORT_` 前缀的环境变量用于配置覆盖。公司网关使用的 `DEEPSEEK_API_KEY` 是独立环境变量，不通过这组 YAML 文件提供。

## 常用命令

公司凭据可在 Windows“系统属性 → 高级 → 环境变量 → 当前用户变量”中设置为 `DEEPSEEK_API_KEY`，值由用户在本机输入。重新打开执行程序后运行 `doctor --strict`；真正启用时仍需由任务进程核验可见性。无需把凭据粘贴到聊天或命令行参数中。

已经打开的 PowerShell 不会自动获得后来设置的用户变量，可在该窗口执行以下命令，仅将值传给本次会话及其子进程，命令不会输出凭据：

```powershell
$env:DEEPSEEK_API_KEY = [Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY', 'User')
```

在项目根目录执行：

```powershell
# 本地预检：允许更新扫描索引和清单，模型调用为零。
uv run python main.py daily --target-date 2026-10-11 --dry-run

# 生成指定自然日的正式日报。
uv run python main.py daily --target-date 2026-10-11

# 模型预览：不发布日报，仍记录调用额度与审计信息。
uv run python main.py daily --target-date 2026-10-11 --no-save

# 主动补充给模型的用户陈述。
uv run python main.py daily --target-date 2026-10-11 -i "本人已复核采购记录，待业务负责人确认。"

# 明确要求重新生成；仍受运行次数和当日总次数限制。
uv run python main.py daily --target-date 2026-10-11 --regenerate --reason "复核摘要表达"

# 只重放数据库保存的精确正文，扫描和模型调用均为零。
uv run python main.py repair-output --target-date 2026-10-11

# 查看阶段、质量、错误码、调用次数和文件位置。
uv run python main.py runs --target-date 2026-10-11

# 检查配置、依赖、原生扫描器和解析进程。
uv run python main.py doctor --strict

# 向公司网关发送固定合成材料，检查路由、JSON 和来源引用。
uv run python main.py doctor --check-model
```

`daily` 未指定日期时采用昨天。`--date` 保留为弃用别名，现在同时决定扫描时间窗和日报日期。当天及未来日期会被拒绝。

`--scheduled` 给任务计划程序使用。北京时间 09:00 前的最近到期日为前天，09:00 起为昨天；它不能与显式日期、预检、模型预览或强制生成组合。多日未运行时，仅为最新到期日新建扫描；其他遗漏日期列在报告中。已有完整输入快照的旧运行可以恢复。

## 扫描范围与覆盖

默认解析 `.docx`、`.xlsx`、`.xls`、`.pptx`、`.pdf`、`.txt`、`.md`、`.csv`。默认排除凭据文件、Office 锁文件、临时目录、依赖目录及本程序的数据、报告和日志目录。

云同步根目录和已完整保存在本机的云文件可以扫描。需要云端回填的占位文件会记录缺口，程序不会修改云同步属性。符号链接、目录联接和未知重解析类型默认不会被跟随；已明确排除的目录不会被计为覆盖缺口。

每份文件最多 50 MiB；PDF 最多 5 页，Excel 每表最多 50 行，文本每文件最多 6000 字符，原生摘录总计最多 50000 字符。CSV 保留现有最多 3 行样本。解析、摘录和模型输入的截断分别记录，样本不用于推算整份文件的总量。

原文件与摘录各有独立 SHA-256 校验值。原文件在读取期间变化时，允许一次额外扫描尝试；仍不稳定或退出原时间窗的候选会保留缺口。相同日期的缓存命中仍保留来源。

| 报告状态 | 含义 |
| --- | --- |
| `complete` | 候选均成功，当前流程未记录覆盖缺口 |
| `partial` | 有可用材料，同时存在截断、跳过或读取缺口 |
| `no_changes` | 扫描完整，目标日期没有候选，也没有用户陈述 |
| `unavailable` | 缺少可用证据且存在采集失败；仅保存诊断，不发布成功日报 |

## 模型请求与复用

固定规则放在 `system` 消息中，摘录和用户陈述放在 `user` 消息中。来源中的操作要求只按材料处理。模型返回摘要与待核实事项，每条必须引用本批提供的来源 ID；日期、质量、路径和计数由本地程序填写。

每批优先保留 1 至 4 条核心摘要，最多 6 条；同主题方案、结果和口径合并表述。待核实事项每批最多 3 条，只保留材料直接显示的矛盾或明确未决问题。模型不能从修改时间推断内容变化，不能把某个分片没展示的信息判为整份文件缺失；来源与截断限制统一由本地程序呈现。

完整请求体序列化后最多 16000 个 UTF-8 字节，每批最多 8 个来源，最多 8 批。请求体包含模型参数、输出结构约束和消息。按完整段落或表格行切分；超过上限的内容会在覆盖记录中披露。分批结果在本地合并，无需再进行一次整篇模型汇总。

每个逻辑请求最多 3 次尝试；JSON、来源引用或输出截断错误最多重试 1 次。认证、权限、路由和确定参数错误立即停止。SDK 的自动重试已关闭，HTTP 重定向也不会静默切换请求目标。

每次真实发送前，短事务先记录调用。每个逻辑运行最多 12 次，实际北京时间自然日累计最多 30 次，包含预览、合成联调及周期报告。恢复沿用原有额度；发送后中断的记录标为结果未知，并保留已占用次数。

请求超时最多 120 秒；应用使用 15 分钟的协作停止预算，Windows 任务使用 20 分钟的执行上限。请求、退避和重试都检查剩余预算。网络等待或文件系统调用可能无法立即终止，任务的硬时限负责最终终止进程。

普通重跑会重新核对本地来源指纹。输入一致时复用原结果；文件缺失可直接修复。成功请求及其响应独立保存，扫描缓存被清理后仍可恢复；已发布报告不依赖中间响应继续修复。

## 本地附注

把人工附注保存在 `data/report_notes/YYYY-MM-DD.md`，文件使用 UTF-8，最多 64 KiB。附注在本地合并到日报，内容不会发给模型。

修改附注或报告模板后，普通重跑仅重新渲染和发布，可复用摘要与原生成时间。`repair-output` 则重放已经提交的精确正文，保留原附注和原模板效果。

## 失败恢复与文件冲突

运行阶段按可靠检查点前进：

```text
created → scanning → prepared → generating → db_committed → published
```

`status` 单独记录运行、失败、取消或成功；失败不会抹掉已完成阶段。`prepared` 表示输入、请求计划和校验值已持久保存。扫描或网络请求期间不保持 SQLite 写事务。

| 情况 | 处理方式 |
| --- | --- |
| 未保存完整输入即中断 | 下次创建新的扫描尝试，保留旧尝试诊断 |
| 已有输入，部分模型批次成功 | 校验快照，复用成功批次并继续剩余批次 |
| 冻结配置与当前配置不同 | 停止恢复，报告 `RECOVERY_CONFIG_CHANGED`；核对后使用原配置恢复或带原因重新生成 |
| 正文已提交，主文件缺失 | `repair-output` 写出已存精确正文 |
| 主文件等于待发布正文 | 补记成功并切换当前日报记录 |
| 主文件等于上一已发布正文 | 原子替换，并保存被替换版本 |
| 主文件包含未知手工修改 | 保留主文件，候选写到 `data/reports/conflicts/` |
| 读取主文件与替换之间发生外部编辑 | Windows 同时捕获被替换副本，保留候选；停止推进当前日报 |
| 输入快照缺失或损坏 | 尚未提交的运行停止恢复；已提交正文仍可修复 |

显式 `--regenerate --reason` 创建的新版本成功发布后，同日更早的未完成尝试标记为 `RUN_SUPERSEDED`，退出自动恢复队列。它们的请求仍计入额度，记录和快照遵循正常留存时间；新版本发布失败时，旧尝试继续保留恢复资格。

数据库先保存完整 JSON、精确 Markdown 与 SHA-256。主文件核验通过后，才在同一事务中更新 `published` 和 `daily_reports`。因此输出冲突期间，周报和月报仍读取上一次已交付版本。

常规冲突可先把人工内容整理到独立附注，将主文件恢复为上一版本或移到个人备份目录，再执行 `repair-output`。发生 `OUTPUT_CONFLICT_CAPTURED` 时，`conflicts` 中的 `.replaced.md` 保存最后窗口内捕获的内容；先核对并处理副本，再将主文件恢复为上一已发布正文后修复。不要直接删除全部冲突文件。

跨进程锁固定在报告库旁，由操作系统持有文件句柄，等待上限 5 秒。进程退出会释放锁；锁文件存在本身不表示锁仍被占用。无需通过删除锁文件恢复运行。

## 留存与迁移

当前正式日报、完整正文和来源元数据长期保存。中间输入、请求及响应快照在运行结束 14 天后清理；未完成恢复所需的数据会被保护。已终结、非当前且无恢复依赖的历史尝试保留 30 天。

快照总量上限为 512 MiB。程序先清理符合到期条件的自有文件；仍不足时，在发送模型前停止。重定向路径、不认识的文件和未完成恢复数据不会为腾出空间而删除。

报告库迁移前使用 SQLite 一致性备份接口生成 `data/db/backups/` 下的备份，检查完整性并保存校验值。迁移和版本标记在一个事务中提交，重复执行不会重复备份或改写旧日报。扫描库仍为 schema 3。

新版日报使用 `schema_version=2`、`report_kind=file_evidence`。旧日报的四字段结构保留，旧有完成事项和计划按原语义读取。周期汇总包含实际存在的周末日报；启用自动日报后，缺失日期按自然日计算。

本次优化回退时，先暂时禁用本项目任务，确认没有运行中的进程并取得应用锁；保存当前报告库的一致性副本，再恢复经过哈希核验的完整旧代码、实际配置、环境和原生组件。最新报告库、全部模型调用记录、已发布报告及未完成快照继续保留，未完成的新范围快照由相容版本显式恢复。核对当前报告可读、调用账本完整及原任务定义后，恢复既有任务。

任务采用当前普通用户的交互式登录令牌。每日 `09:00 +08:00` 和用户登录后 1 分钟各有一个触发器；允许补执行，重复实例采用 `IgnoreNew`，电池供电可运行，不唤醒设备，失败重启最多 2 次、间隔 15 分钟。

程序使用项目 `.venv/Scripts/pythonw.exe`，参数包含带引号的绝对 `main.py` 路径，工作目录固定为项目根目录。用户需要保持登录，电脑需要具备执行条件。环境变量变更后，以实际任务进程的运行记录确认可见性。

每次定时进程启动会记录 `scheduled_start`、运行 ID、目标日期、进程 ID 和 `credential_env_present` 布尔值。该记录只证明进程是否获得环境变量，不包含凭据；成功记录 `report_run` 可与数据库和日报文件对应。

安装脚本默认预览。`-Apply` 要求本机严格检查通过、公司环境变量可见、模型容量已配置且当前配置有成功的合成模型检查。重复安装相同配置不会覆盖任务；同名任务属于其他项目时拒绝处理。变更已存在的本项目任务前保存 XML 备份，读回不一致时禁用任务并报错。

暂停自动运行可使用任务计划程序中的“禁用”，或在核对任务名和项目归属后运行 `Disable-ScheduledTask -TaskName 'AI Daily Report'`。任务的注册、禁用和移除都需要明确执行相应命令。

触发时间、设置与 XML 元素依据 Microsoft 的 [任务计划程序架构](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-schema)、[带时区的开始时间](https://learn.microsoft.com/en-us/windows/win32/taskschd/trigger-startboundary) 和 [失败重启定义](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-restartonfailure-settingstype-element)。

## 错误与覆盖优化的运行口径

覆盖以唯一来源计算。每个来源归入“有有效摘录、未解析、解析失败、摘录为空”中的一类，并保留一个主原因。次要标签补充图片观察、OCR 未核实或历史内容变化等信息，不重复累计来源数。

以下四层分别保存，不能互相替代：

1. **实际读取**：解析器读过的 PDF 页、工作表物理行、段落、幻灯片或字节区间。
2. **有效摘录**：保留了哪些完整内容单元；重复表头只提供语义背景。
3. **模型成功输入**：成功响应对应的字符区间联合长度。预约、发送尝试、缩批前计划和未知结果分别记录。
4. **正文引用**：摘要实际引用的来源。

新字段进入 scanner profile（扫描配置身份）、解析缓存及模型请求指纹。旧记录缺少页行或字符范围时保存未知值；读取旧记录不会推算补齐这些字段。

摘录使用 `fair_semantic_v9`：按文件类型轮转，先为每个可用来源分配一个完整内容单元，再利用剩余额度加深。模型批次同样先安排来源首片，按真实 UTF-8 字节计算完整请求大小。缩批只发生一次，修订输入持久保存，恢复复用实际成功修订。

`budget_refill_v3` 最多补缺两轮。只回收经过确认未消耗的预约，失败或结果未知继续占额。候选名额、分类页数、正文提取名额、总字符数和截止时间各自约束；补缺不增加原上限。

PDF 新策略为 `pdf_text_presence_v2`：在原页额内检查前两页、末页及均匀抽样页；有文字后停止分类。审计区分实际检查页与名额预约。正文提取按明确的页列表进行。`pdf_window_no_text` 仅表示已读窗口无字；实际看到图片时才记录图片观察。加密、损坏、超时和运行环境缺失具有各自诊断。缓存命中保留历史页列表，本次检查页数为零。

Excel 根据容器格式选择解析器：`.xls` 名称的 XLSX 按 XLSX 读取；真实 XLS 需要显式启用 legacy office（历史 Office 格式）。XLSX 保持物理行窗口，历史 XLS 保持“表头加数据行”的旧合同。窗口外合计继续为未知，不把窗口内小计标为全表合计。

CSV 默认允许 UTF-8 与 UTF-8 BOM（编码标识）。需要 GB18030 时在本机配置 `scanner.csv_encodings` 中显式加入；示例配置已展示该列表。内部非法字节返回受控错误，窗口边界不会输出半个字符或半条记录。

## OCR 文本入口

OCR（图片文字识别）默认禁用，不安装识别引擎。显式调用独立 OCR worker 时使用单独的文件数、页数、字符数和运行时间额度。导入清单必须绑定原 PDF 的 SHA-256、原页数、唯一页号列表、UTF-8 识别文本及其 SHA-256；原文件和识别文本在读取期间变化会被拒绝。

导入文字的解析来源为 `local_ocr_import_v2`，保留真实页号和 `text_unverified`。引用这些文字的陈述进入待核实项；数字不会因成功导入而自动被认定正确。旧清单缺少文本哈希时需要补齐清单，不能直接复用为新证据。

## 显式历史补覆盖

新的历史候选作业位于 `data/coverage_repair/<job_id>/`，包含冻结 `plan.json`、独立 `state.json`、追加 `events.jsonl`、来源临时副本和每日期候选 JSON、Markdown、差异。原 183 天作业及额度保持独立。

按照需要复核的日期和缺口码创建计划。`--scope-root` 必须覆盖这些日期既有报告的全部登记来源；后续只读取冻结计划中的明确文件。下例中的预算是本地演示值，实际执行使用核实的币种、网关单价与作业金额上限。

```powershell
# 只读取报告元数据，不读取业务文件，不调用模型，不发布。
./.venv/Scripts/python.exe scripts/backfill_daily_reports.py `
  --repair-coverage --dates 2026-09-22 `
  --gap-codes MODEL_INPUT_BOUNDED --scope-root 'D:\approved-work' --dry-run `
  --call-budget 12 --token-budget 300000

# 同一预检命令增加 --refresh-preflight：读取批准文件、冻结当前哈希，
# 在作业专属目录执行本地 scanner；模型调用仍为零。

# 校验冻结范围、源码/配置身份和预算，生成候选；正式日报继续为旧版本。
./.venv/Scripts/python.exe scripts/backfill_daily_reports.py `
  --repair-coverage --plan 'D:\job\plan.json' --generate-candidates --workers 3

# 审阅候选及差异后，发布已存正文；扫描和新增模型调用均为零。
./.venv/Scripts/python.exe scripts/backfill_daily_reports.py `
  --publish-candidates 'D:\job\candidates.json'
```

实际候选生成要求计划具有 `pricing` 和 `--cost-budget-microunits`。费用使用币种的百万分之一单位整数表示；1 元对应 1000000。费率设置为每百万 token 的币种微单位 `input_per_million_microunits`、`output_per_million_microunits`，并指定 `currency`。缺少真实 usage（模型用量）时保留保守上界，未知调用不归还预算。日常上限继续生效，新作业不能沿用旧作业的 650 次额度。

重复生成使用原候选 run ID、generation（生成身份）及成功响应。文件或算法身份改变时，建立新的具名计划；旧调用记录继续保存。历史文件当前内容与原日报哈希不同会标记 `HISTORICAL_CONTENT_CHANGED`，候选说明无法还原原日期内容。

候选发布核对候选快照、正文、差异、旧当前 run ID 及主文件实际哈希。发生手工修改或版本变化时，保留旧当前版本与冲突候选。中断发布只能由相同 `--publish-candidates` 命令恢复，普通日常恢复不会自动发布候选。

事件先刷盘，再原子更新进度视图。尾部不完整事件先保存准确字节备份，再有界恢复；完整事件损坏时停止。候选输入和调用账本受到恢复留存保护，使用前检查 512 MiB 快照总额；不会为腾出空间自动删除待审候选。

## 内容分配与事实保留

`fair_semantic_v9` 先为每个有效来源分配完整首份内容，再保留原文合计，并交替分配数量条件和必要限定，最后增加普通正文深度。同一章节的段落按共同标题和表头判断优先级，避免重复拆段挤占内容。包含数值的表格行保持完整；未带数字的业务限定、并行关系和不可用状态也保留分配机会。历史候选中，原报告已有内容哈希且与当前冻结原文件字节一致的来源，通过 `excerpt_priority_paths` 获得后续内容优先级。其他来源仍保留首份机会；旧摘要不作为新模型证据。

旧报告缺少来源内容哈希时，历史版本保持未知，记录 `HISTORICAL_CONTENT_UNKNOWN`。只有新旧内容哈希都存在且不同，才记录 `HISTORICAL_CONTENT_CHANGED`。冻结现有文件用于候选，不能证明旧日期的文件版本。

`source_first_semantic_v11` 在同一 8 批、每批 16000 字节上限内安排来源。历史优先来源的首片分散到各批，之后再分配深处内容。模型看到的 `history_priority=true` 仅表示已核验来源身份及优先顺序。每条摘要仍需由本次提供的原文支持。

当前输入范围版本为 3。实际请求保留来源 ID、路径、类型、内容、截断状态及必要的文字待核实标记；每个完整内容单元和页、行、段落位置保存在本地 `input_audit`。读取快照时，程序逐项核对审计内容与请求的实际文本。版本 1、2 的已有快照继续按原版本校验，不能把新版本字段反填到旧请求。

Markdown 表格的表头和对应数据行作为完整内容单元保留。XLSX 的两层表头按列合并，保留姓名、月份和金额字段之间的关系；未标姓名的数值行保留原字段与物理行号，其性质由来源证据核对。读取窗口统计与人员分月金额按表格行保留，原表明确的合计另有合计优先级；这些内容各自保留范围，缺少币种时不补写币种。

审批矩阵中相邻的金额行与公司、合同类型行可生成紧凑摘录，保留两行的实际位置。只有一个金额档且完整文本能够容纳时，一并保留同列的审批流；多个金额档分别保留其原文关系。长审批流程继续受现有字符额度约束。金额档归属、标准与非标准合同差异及已读范围内的统计可以核对；窗口之外的信息继续保留缺口。

## 同版构建与回退

最终验收使用经过 `maturin --auditwheel repair` 修复的 CPython 3.13 Windows wheel（安装包），以及相同源码身份的 Office worker。发布包核验每个文件的哈希和 worker 握手；严格诊断在独立 installed mode（安装模式）的 `shared/` 路径下执行。

未提交候选的证据包含 HEAD、工作区补丁、未跟踪源码哈希、发布清单及测试日志哈希。后续源码变化或 Git 提交需要重新核对构建身份。

本次优化不提供绕过新范围校验的运行开关。需要回退时恢复经过核验的完整旧代码包及配置，保留当前数据库、调用账本、候选和未完成快照；新快照由相容版本显式恢复。生产每日 09:00 任务保持一个，切换与三个真实触发窗口的验收单独留证。

### DeepSeek 思考模式与失败恢复

`llm.thinking_mode` 可设为 `enabled` 或 `disabled`，缺省不发送该参数。该开关保存到计划与请求指纹，完整 UTF-8 正文计算包含 thinking 字段，初始请求与缩批保持同一设置。180/120 字符上限包含中文、数字、英文、空格和标点。官方参数说明：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

`llm.thinking_parameter_location` 指定参数位置：`top_level` 使用顶层 `thinking`；`extra_body` 使用嵌套 `extra_body.thinking`。未设置位置时保留原顶层格式。显式位置必须配合显式的 `thinking_mode`；请求位置参加配置、计划及恢复指纹。SDK 实际发送正文与冻结正文已经通过本地模拟验证。

`ai-gateway.fsdev.cn` 公布 LiteLLM 1.91.0，真实样本中顶层 `thinking.type=disabled` 仍产生大量推理 token。嵌套 `extra_body.thinking.type=disabled` 的合成请求返回正确 JSON、42 个输出 token且无返回推理内容；响应未提供推理 token 计数。正式配置、冻结请求及部分成功恢复集成已经通过本地回归；真实文件候选质量尚待验收。推理 token 缺失时保持未知，不能仅凭配置中的 disabled 值声称网关已经关闭思考。

历史作业因已确认原因失败且全部调用均为明确失败时，可用 `amend_failed_execution(config, plan_path, reason=...)` 记录一次执行修订；计划和样本保持冻结，追加事件及 execution-amendment.json 绑定新的配置与算法。未知或已成功的作业拒绝重启。所有原失败调用继续占用同一 job_id 的调用、token 和金额额度，达到原总额时拒绝发送；新运行记录继承已用次数。修订期间中断时重复执行同一方法，事件和已完成修订不会重复。

已有部分成功结果的作业使用 `prepare_execution_recovery(config, plan_path, reason=..., authorization_note=..., calls_limit=...)`。该方法只准备输入，新增模型调用为 0；原计划及旧执行修订保持冻结，新修订绑定旧调用、成功响应与实际范围。缩批遗漏内容通过独立完整原输入补充请求恢复，未开始的日期也在准备阶段冻结。总调用上限提高需要明确的范围授权；登记后，所有新旧请求继续共用原作业总额度，旧预约保留原值。重复准备不会创建重复调用或退回已完成候选。

历史样本作业保留原 38 次调用与三份 V25 候选。用户于 2026-10-13 取消预算并停止对样本输出逐条迭代，9 个针对性请求不再执行。旧预算和质量失败证据保持，后续不再要求额度确认。当前生产为 V27，预算开关已关闭；一次普通真实预览新增 8 个正常分批请求，随后生产离线复用全部结果，没有追加内容修复请求。
