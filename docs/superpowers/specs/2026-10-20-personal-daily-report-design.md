# 个人日报精简设计

日期：2026-10-20。用途：指导个人日报的选材、生成和保存改造。本文中的数值是设计默认值与验收目标，实际效果以实现后的验证为准。

## 1. 产品目标与范围

每天自动整理工作文件中的有效变化，结合可选的几句人工补充，帮助用户回顾进展、留意问题并接续工作。

已确认的产品取舍：

- 日报主要供用户自己回顾与安排。
- 人工补充可选，适合会议、沟通和临时决定。
- 长期保存最终日报和关键依据；不提供任意历史文件版本的恢复能力。
- 材料超预算时只处理选中部分，提示未展开范围；接受未选材料中可能存在重要信息。

推荐复用现有白天采集和解析能力，限制后续材料、调用和保存规模。每日只读取一次文件也能运行，但会遗漏两次读取之间出现又消失的变化；保留现有白天采集更符合当前项目条件。

继续使用既有工作目录、模型提供方及允许发送的目录范围；OCR 保持关闭。当前工作日采集窗口与次日晨间生成安排继续适用。新增默认日报采用本设计；已有报告、冻结输入和历史恢复按原格式读取。周月报和搜索需要能读取新日报，不增加独立产品功能。

## 2. 用户看到的结果

正文围绕“进展、留意、下一步”组织，同一事项集中说明，通常 3～7 项，最多 10 项；少量变化允许少于 3 项。正文目标 500～1,000 字，最多 1,500 个 Unicode 字符，来源摘录单独计算。

每项包含简短结论和来源；需要跟进时附下一步。来源中明确的安排与程序推断的建议分开标识。文件更新、事项完成、方案批准和制度生效分别需要对应依据。人工补充标注“用户补充”，程序不得替用户确认完成状态、责任人或截止时间。

示例：

> **采购方案调整**：新增两项交付要求，报价仍待确认。
>
> **下一步**：周五前确认报价与交付时间。
>
> **依据**：采购方案.docx，第 3 节；当天用户补充。

只有原材料明确支持时，才能生成上述具体表述。

报告末尾用一段话说明本次材料范围、未展开部分和影响使用的缺口。正常选材省略与读取失败分别统计；不得把未选材料登记为已完整总结。内部请求编号、重试细节等进入运行记录。

## 3. 材料范围与选择

流程：发现变化 → 有界解析与比较 → 本地选择材料 → 一次模型生成 → 来源检查 → 本地排版与发布。

- 自动日报仅处理目标日实际观察到的变化，日期使用 Asia/Shanghai。较早遗漏按日期提示，补报由用户主动发起；旧积压不会持续灌入新日报。
- 同一文件多次修改，使用目标日开始前最近可用版本与目标日最后观察版本比较。中间版本仅用于短期处理。缺少前版时标为首次读取或无法比较，不把全部内容认定为当天新增。
- 首次建立观察状态本身不构成业务进展。文件在两次采集之间改变又恢复、或变化发生在未覆盖的时间内，可能无法观察到。
- 在现有权限和排除规则内去除重复材料、临时文件和能够确认的纯格式变化。解析不完整时保留缺口，不凭相同的局部文字宣称整个文件无变化。
- 表格以完整的相关行或区域为选择单位，同时带上表头、单位、行标识和必要的前后值；文档带上必要标题及上下文。不在数值、条件或变化前后配对中间截断。
- 优先考虑用户补充、明确的截止与阻塞提示、状态或关键字段变化。排序采用可解释的本地规则；这些规则只决定材料优先级，不证明事项的重要性。
- 先让不同文件获得候选机会，再补充同一文件的材料，避免一个大文件占满输入。相同输入与配置产生相同选择结果。候选遍历、读取和排序均受时间、数量及内存上限约束，不先复制全部正文再截短。
- 输入业务文字总计最多 20,000 个 Unicode 字符，包含人工补充及必要上下文。人工补充优先预留，单日补充合计最多 2,000 字；超限明确报错并保留原文，提示用户缩短，不静默截断。
- 实际请求还须通过既有 UTF-8 字节和已验证模型上下文限制。任一限制更紧时，继续按完整材料单元减少输入，记录未选范围。

复用命令行 `-i` 和按日期保存的备注文件。两类补充统一进入选材与生成，并按相同内容去重；日期备注不再仅作为报告尾部附文。没有补充文件时正常运行。更改已发布日期的补充需要显式重生成，定时运行不自动覆盖已发布报告。

## 4. 生成、预算与异常

| 对象 | 默认规则 |
| --- | --- |
| 模型请求 | 通常一次生成结构化重点；每个工作范围、目标日期累计最多 3 次自动请求 |
| 重试计数 | 发送前持久化预占额度；失败、超时、结果未知和无效响应均计入，重启及兜底触发共用额度 |
| 并发 | 日报生成单并发，避免同时消耗剩余额度 |
| 单次日报 | 正常目标 180 秒内；应用总预算 300 秒，包括等待锁、准备、生成、检查和发布 |
| 收尾 | 从总预算中预留 30 秒停止新处理并保存结果；请求、Worker 和本地循环使用剩余预算 |
| 输出 | 日报文件与独立关键依据文件合计最多 100,000 字节 |
| 无变化 | 成功检查且无变化、无补充时，生成简短状态，模型请求为 0 |

请求额度按目标日期计算，不能仅沿用现有的“单次运行”和“实际调用日”限制。精简日报的硬上限始终有效，不受旧配置关闭累计预算的开关影响。正常手动重跑共享已用额度；额外付费请求需要显式授权，后台不自动增加额度。

模型直接返回事项、类型、简短文字和来源编号。程序检查来源编号存在、摘录确实在本次输入中、位置及内容指纹一致，并拒绝把待确认内容标为已确认。上述检查不能自动证明所有语义推断正确，验收需包含金额、条件、批准状态和行动建议的人工可读样例。

新格式校验已选事项的内容与来源，不要求每条输入材料都进入正文。旧格式的完整覆盖校验保留其原有含义。省略原因使用确定类别：重复、范围外、预算未选、读取失败或无法比较；只保存必要计数及有限路径样例。

结构或引用无效时，在剩余额度和时间内重试。已验证输出仅因篇幅过长时，按优先级保留完整事项及其全部必要依据，不为润色增加请求。任何无法独立获得支撑的事项整体移出，最终重新检查字符数与字节数。

模型失败或预算耗尽时，本地生成明确标注的有限结果：保留用户原文、已核实的变化概况和缺口，不把原始文件清单写成已确认成果。无可用内容时生成失败状态说明。已发布的有限结果不会被后续自动触发反复重写；发布中断只复用已验证内容修复输出。

扫描失败、部分读取、缺少旧版和确认无变化使用不同状态。运行错误继续提供 `error_code`、`message`、`retryable`。应用停止新工作与外部调度超时兜底需要分别验证；进程被强制终止时，不宣称结果已成功保存。

## 5. 保存规则与空间边界

| 类别 | 保存规则 |
| --- | --- |
| 日报与关键依据 | 长期保存，包含来源路径、位置、观察时间、必要原文摘录及内容指纹；数值调整保留必要前后值 |
| 人工补充 | 随对应日期保存相关原文，作为用户来源；计入最终材料大小 |
| 当前文件状态 | 每个当前文件只保存路径、指纹和最近处理位置；移出观察范围后的无引用状态定期清理 |
| 调用额度 | 保存每个目标日期的已用额度及结束状态，详细请求删除后仍不能重获自动额度 |
| 处理缓存 | 原件临时副本、解析结果、比较材料、冻结输入、模型请求和响应，最多 7 天且合计不超过 1 GiB |
| 运行明细 | 日期、结果、耗时、调用数及错误原因；详细记录保留 30 天、最多 10 MiB，之后只保留日报关联的汇总 |

1 GiB 指精简流程新增处理区的文件逻辑大小，包含暂存、失败文件、数据库临时文件和在途写入预留。此值不代表整个仓库大小；历史数据、长期报告及开发构建产物另计。

写入前预留空间，清理优先针对已结束且最旧的临时材料。过期或被配额淘汰的旧版本可以失去比较能力，日报须说明；不得因保护“当前版本”而无限延长所有正文的保存期限。活动处理仅在其运行预算内受保护；处理关闭后释放引用，未完成运行不能永久占用缓存。

配额不足且无法清理时，停止对应采集或解析并记录缺口；单个输入或输出超限时跳过该对象，避免先写满磁盘。采集和独立补解析也使用有界处理：每次最多 120 秒，结束后保留仍在有效期内的队列；队列到期明确结束，不无限追赶过期材料。

发布顺序为：核对引用 → 将关键依据写入最终材料 → 校验结构化报告及文件 → 原子发布 → 释放本次临时材料引用。关键依据只引用最终材料中确实存在的摘录，不依赖即将过期的缓存路径。保存或校验失败时不能把报告登记为成功。

按每天 100,000 字节计算，新增日报及依据文件一年约 36.5 MB。数据库内必要的结构化副本、当前状态和程序文件另计。缓存清理后，日报引用仍能定位其自带摘录；原文件可打开时另外提供当前位置链接。

## 6. 现有实现的复用与迁移

复用 Rust 解析器及 Worker 隔离、权限检查、数据库锁、请求账本、输出发布和恢复能力。新日报使用显式版本化的数据格式，关键依据随报告保存；历史读取、搜索、周月报汇总和健康检查同时识别此格式。解析算法与已验证模型配置复用，不新增生产依赖。

已有实现入口：

- [输入准备](../../../rust/report_app/src/run/input.rs)：日期备注、命令行补充和输入计划。
- [归档选材](../../../rust/report_app/src/archive/model_input.rs)：权限、变化与原文位置。
- [报告约束](../../../rust/report_app/src/model/contracts.rs)：原有完整覆盖规则与新格式边界。
- [调用账本](../../../rust/report_app/src/store/calls.rs)：发送前预占及跨运行预算。
- [归档清理](../../../rust/report_app/src/archive/maintenance.rs)：现有报告引用保护，需要与新的短期材料规则区分。

新处理缓存使用独立、受管理的目录，不把现有归档直接改成可自动删除的缓存。采集切换后不继续为新日报建立无限期历史副本；旧报告仍能按旧格式读取。旧冻结运行不会自动套用新选材语义。

实施次序：先完成新的输入、报告、预算及有界采集保存链路，在隔离数据上验收；随后完成正式配置和任务切换；最后按具体清单处理历史占用。实际模型调用、正式切换、历史删除与 Git 发布各自沿用明确授权边界。

历史清理前逐类核对是否被旧报告、未完成恢复或回退版本引用。需要释放被旧报告引用的归档时，先保存足够的独立依据并验证可读性，再提出具体删除清单、影响和恢复方式。现存业务原件、旧包和证据不会仅因本文保存规则而自动获得删除授权。

开发复用固定构建目录；临时测试数据随用途结束清理。正式包最终维护当前版本及一个必要的回退版本，候选版本只在验证期间保留。日常维护集中在使用说明、工程约定和当前状态，不要求每次修复新增方案与结果文档。

## 7. 验收条件

1. 用少量变化、大量修改、重复保存、表格调整和可选补充验证：重点清楚、同一事项合并、最多 10 项，来源与摘录正确，最终文件合计不超过 100,000 字节。
2. 用跨日积压和版本缺失验证：只处理目标日范围，未选材料不被当作完整覆盖；缺少前版不虚构“新增”或“已完成”。
3. 用本地模拟模型验证失败、超时、无效引用、进程中断及重复触发：同一目标日期总请求不超过 3 次，持久化额度不会因重启或清理恢复。
4. 用受控时钟及实际子进程验证总预算、收尾时间和在途工作停止；正常材料实测是否达到 180 秒目标。超过时间目标须报告实测值，不以单项测试代替运行验收。
5. 用小配额隔离目录验证并发写入预留、单文件超限、过期队列和活动处理保护；清理后占用保持配额内，且最终日报、证据及范围外文件完整。
6. 删除隔离测试中的临时材料后，已发布日报仍可阅读与查看关键依据；搜索、周月报和历史旧格式读取均通过。
7. 本地修改按影响运行相关测试；发布前完成项目规定的格式、Clippy、工作区测试和独立程序包验收。正式切换后核对实际任务、配置、存储增长及一次真实日历日报，历史清理独立验收。
